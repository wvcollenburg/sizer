A DR target is a site that holds replicas of other sizings' VMs, for example a secondary data centre. It is sized from the capacity it must reserve for them, not from an import.

Setting up replication

  1. On the project page choose {{ m.ui("Add DR target") }} and give it a name (the default is DR site). It appears in the table as a Replication target, not sized yet.
  2. Open the Options panel (sliders icon) of a sizing whose VMs must be replicated and set {{ m.ui("Replicates to") }} to the DR target. Batch edit can do this for several sizings at once.
  3. Choose how much of the source to reserve: Compute % and Storage % (100% each by default). Lower them when only part of the workload has to run at the DR site.
  4. Choose the mode:
    • Reserved — hold capacity at N-1 (default): the replicas' compute fits even with one of the target's own nodes down.
    • Failover only — replicas run after a site fails: the replicas' compute only has to fit with all of the target's nodes up. That needs less hardware, but leaves no headroom for a node failure during a disaster.
  5. Save. The link appears under Replication on the project page.
{{ m.shot("sizing-panel-replication", "Production replicates to the DR site") }}

Replication is not limited to DR targets: any sizing can replicate into another sizing in the same project (for example two production sites protecting each other). The receiving sizing then shows the reserved capacity above its recommendations, and its bars include a replication band.

Sizing the DR target

Open the DR target from the table.

{{ m.shot("dr-target", "A DR target, sized from its inbound replication") }}
  • Inbound reserve lists what every source sends (vCPU, RAM, storage, percentages and mode) and the total. A source that has not been sized yet is flagged, because it contributes nothing until it is.
  • The options are a compact version of the normal ones: vCPU ratio, projection years, growth, snapshot overhead, sizing mode (and vendor for validated), size for model, and three checkboxes: Allow a single-node target (a DR cluster is already a redundancy tier, so one node can be acceptable), Allow storage-only nodes and Include EOL/EOS models.
  • Pick a recommendation and choose {{ m.ui("Save DR target") }}.
{% call m.note() %}A DR target is not recalculated automatically when its sources change. Its state shows Needs refresh. Open it and save it again. A sizing that others replicate into cannot be deleted until those links are removed.{% endcall %}
