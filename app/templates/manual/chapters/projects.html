After signing in you land on the Projects screen. A project holds the sizings for one customer: several imports, the options you want to compare, and the replication between them.

{{ m.shot("projects-home", "The Projects screen") }}

The Projects screen

ControlWhat it does
{{ m.ui("New project") }}Asks for a project name and opens the new, empty project.
{{ m.ui("Open by code") }}Opens a project from its 12-digit share code. You can open projects of your own organisation this way{% if scale %}; Scale Computing accounts can open any organisation's project (see Opening a partner's work by code){% endif %}.
{{ m.ui("Quick sizing") }}Starts a blank sizing without choosing a project. It is filed in your personal scratch project, marked Personal.
{{ m.ui("Also show my colleagues' projects") }}Off by default: you see your own projects. Tick it to also see the projects of everyone in your organisation. The setting is remembered in your browser.

Each card shows the project name, the customer, the number of sizings, the number of BOM checks and the date of the last change. Projects are sorted by most recently changed. A Shared badge means the project belongs to someone else. You can look at it, but not change it.

Creating a project

{{ m.shot("new-project", "Only a name is needed to start") }}

Type a name and choose {{ m.ui("Create") }}. Customer, opportunity reference, notes and the export language can be added later under {{ m.ui("Details") }}. The project remembers the language the sizer was in when you created it and uses it for exports, until you change it.

The project page

{{ m.shot("project-view", "A project with three imported clusters, an alternative and a DR target") }}

Under the project name you see the opportunity reference and the project's share code. The buttons along the top:

ButtonWhat it does
{{ m.ui("New sizing") }}Opens a blank sizer inside this project. See Creating a sizing.
{{ m.ui("Add DR target") }}Adds a replication target site. See DR targets and replication.
{{ m.ui("Comparisons") }}Compares sizings or tag groups side by side. See Comparisons.
{{ m.ui("Exports") }}Builds proposal documents. The badge counts finished downloads. See Exports.
{{ m.ui("Check a BOM") }}Checks a partner quote against the HCL and the sizing. See Checking a BOM.

A row of tag chips under the buttons filters the table. Click a tag to show only the sizings carrying it, and click it again (or {{ m.ui("Show all") }}) to clear the filter.

The sizings table

ColumnMeaning
CheckboxSelects the sizing for batch editing (see Batch edit).
SizingThe name. Click it to open the sizing. A dot after the name means it has notes; hover over it to read them. An Exports as … badge means the exports describe different hardware from the recommendation (see Exports as).
TagsThe sizing's tags.
RolePart of total (a site or phase that adds up with the others) or Alternative (one of several competing options). See Roles.
SourceThe imported file name, Manual, or Replication target.
StateSee below.

The State column tells you whether a sizing's result can be trusted:

StateMeaning and what to do
To be sizedCreated from a multi-cluster import and not reviewed yet. Open it, check it and save it.
Re-importThe file was read by an older version of the importer that has since been corrected. Recalculating cannot fix this: import the file again.
Not sizedNo result has been saved yet.
Needs refreshThe hardware catalog, the sizing rules or a replication source changed after this sizing was saved. Opening the project recalculates these automatically.
CurrentUp to date.

When you open a project that has sizings in the Needs refresh state, a bar shows Recalculating 1 of 3… while the sizer brings them up to date in the background. If one cannot be recalculated automatically, the bar says so. Open that sizing to see why. DR targets and Re-import rows are never refreshed automatically.

Row actions

On your own projects each row has four icons on the right:

IconWhat it does
Sliders (Options)Role, tags, notes and replication for this sizing. See The Options panel.
Server (Exports as)Which hardware the exports describe. See Exports as.
Copy (Duplicate)Makes a copy of the sizing in the same project, named … (copy).
Bin (Delete)Deletes the sizing after a confirmation. A sizing that other sizings replicate into cannot be deleted until those replication links are removed. The sizer names them.

On a project that is not yours (a colleague's{% if scale %}, or one you opened by code{% endif %}) the only action is Copy to mine. It copies the sizing into a project of your own and takes you there, so you can change it without touching the original.

{% call m.note() %}A sizing cannot be renamed once it is saved. To give it a different name, open it and use {{ m.ui("Save sizing") }} → {{ m.ui("Save as new") }}, then delete the old one.{% endcall %}
