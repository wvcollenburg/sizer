The recommendations are the SC//HyperCore configurations that meet the workload with N-1 redundancy, best first. Up to eight are shown.

{{ m.shot("wizard-recs", "Step 5: the recommendations, ranked") }}

The list

  • Each row shows the model, its storage layout, the node count, the per-node shape (cores, RAM, storage), how full the cluster will be (CPU, RAM, storage) and the resulting vCPU:core ratio. Columns appear as the window gets wider.
  • The resource marked limiting is the one that decided the size of the cluster.
  • Under every row but the selected one, a Δ per node line shows how it differs from the selected option.
  • {{ m.ui("Select") }} makes a row the chosen option. It is not saved until you save the sizing. The chosen option is what comparisons and exports use.
  • Click a model name or the arrow at the end of a row to open its details (one at a time).

The details of an option

{{ m.shot("rec-card", "An opened recommendation") }}
  • Determined by says which resource sized the cluster, and how much headroom is left on it.
  • The CPU performance and compute floor lines compare the new CPUs with the current ones (see CPU performance).
  • The licence line says what SC//HyperCore licensing the cluster needs: cores per node for the term, or an Essentials kit for small clusters. Prices are never shown.
  • Three tables: Per Node, Total and N-1 available, the capacity left with one node down.
  • The utilization bars show, per resource, how the cluster is used: today's workload, snapshots, growth, replication reserve, the high-availability reserve (the node that may be down) and what is free. The first percentage is today, the second is at the end of the projection.
  • The IOPS headroom compares what the cluster can deliver with what the workload needs.
  • The footer names the form factor and chassis. For validated sizings it says which SC// model is the equivalent.

{{ m.ui("Network") }} opens a cabling diagram of the cluster: switches, LAN uplinks and the backplane connections of every node. {{ m.ui("Download SVG") }} saves it as an image.

The Quoted row

When the exports of a saved sizing describe different hardware from the recommendation (through a BOM check or a manual override, see Exports as), a row marked Quoted appears at the top of the list. It shows that hardware measured against the same workload. Exports always use it, whichever option is selected. Values over 100% are shown in red.

Assumptions

Under the list, the Assumptions block repeats every input the sizing used (ratio, growth, caps, storage type, sizing mode). Check it before you share a result.

When nothing fits

Warnings above the list explain when a setting cannot be met. For example, the target node count is too small for the workload. When no configuration fits at all, try a higher vCPU ratio, a different storage type, allowing storage-only nodes, or Validated mode.
