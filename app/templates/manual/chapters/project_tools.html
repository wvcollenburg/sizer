Back on the project page, a few tools organise the sizings so they compare and export correctly.

Roles: part of the total, or an alternative

Every sizing has a role that tells the comparison and the exports how to treat it:

  • Part of the total: a site, cluster or phase. These add up. For example Production + Remote-Office + Test-Dev is the whole estate.
  • Alternative: one of several competing options for the same workload, for example hybrid versus all-flash. Alternatives are never added together.

Sizings created from a multi-cluster import start as Part of the total.

Batch edit

Tick the checkboxes of several sizings. A bar appears with the number selected, {{ m.ui("Batch edit") }} and {{ m.ui("Clear") }}.

{{ m.shot("selection-bar", "Two sizings selected") }} {{ m.shot("batch-edit", "Batch edit: every field starts at Leave unchanged") }}

Batch edit changes the role, adds or removes tags, and sets or removes replication for all selected sizings at once. Anything left at Leave unchanged is not touched. {{ m.ui("Apply to selection") }} applies it.

Exports as

By default an export describes the recommended hardware. When the customer is actually buying something slightly different, for example a partner's quote for a comparable server, the server icon on the row sets what the exports describe:

{{ m.shot("export-as", "Exports as: choose the hardware the documents describe") }}
  • Hardware source: Automatic (the default) uses the most recent BOM check of this sizing that passed and does not come out smaller than required, and otherwise the recommendation. A failing check is never picked automatically. You can also pick The recommendation or one specific BOM check. Checks that failed, or that come out smaller than required, are flagged in the list.
  • Override by hand: fill in any field (chassis, vendor, form factor, CPU, cores, threads, RAM, nodes, and up to two disk tiers) and it wins over the source, field by field. Leave a field empty to keep what the source says. The chassis field suggests models from the HCL as you type.
  • {{ m.ui("Use the recommendation") }} removes every override.

While an override is active, the row shows an Exports as … badge, the sizing shows a Quoted row, and every export describes that hardware: capacity bars, licensing and compute all follow the quoted hardware.
