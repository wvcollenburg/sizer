The options apply to Assessment Import and Manual Input. In the wizard they are on step 4. In the classic view they are in the column left of the recommendations, in three panels you can fold open. Every change recalculates the recommendations straight away.

Platform

OptionDefaultWhat it does
Sizing ModeCertifiedCertified sizes on SC// appliances with their fixed hardware. Validated (Software-Only) uses the same models but allows the disk count per node to be reduced (never increased), so storage fits the need more closely. It keeps to the hybrid flash band and the maximum number of disks per cluster, and leaves out models that mix NVMe and SSD.
Vendor—Validated only. The server vendor to build on. Only models the HCL lists for that vendor are recommended, and they are named after the vendor's chassis (for example a Dell or Lenovo model) rather than the SC// name.
Size For ModelAll models (best fit)Restricts the recommendations to one model. Leave it on All models to let the sizer pick the best fit.
Include EOL / EOS systemsOffAlso considers models that are end-of-life or end-of-support. Useful when extending an existing cluster.

Sizing Options

OptionDefaultWhat it does
Target vCPU : Core ratio3 : 1 (set by the administrators)How many virtual CPUs share one physical core. Slide left (towards 1:1) for demanding workloads such as databases, right (towards 8:1) for light ones such as VDI or test. The marker labelled Current shows the ratio of the existing environment. Every sizing starts at the default, not at the current ratio.
Target Node Count (advanced)blankSizes to exactly this many nodes (minimum 2). Larger clusters are only offered, with a warning, when the workload does not fit. Leave it blank for the best-fitting, best-priced solution.
Size CPU for full cluster (advanced)OffNormally CPU is sized so the workload keeps full performance with one node down (N-1). Ticking this sizes CPU across all nodes instead. That needs fewer or smaller nodes, but during a node failure the vCPU:core ratio rises and performance can drop. The cards then show the ratio you would run at with a node down.
Storage TypeAutoPrefer All-Flash, Hybrid (HDD with a flash tier) or All-Spinning. Auto considers all of them.
Allow storage-only nodes (advanced)OffWhen storage needs more nodes than compute does, the extra nodes (beyond two full nodes per cluster) become storage-only nodes: no VMs, a single small CPU and minimal RAM, but full storage and IOPS. This lowers compute licensing for storage-heavy workloads.
Include … GB found on local storage (advanced)OffOnly shown when the import found VM data on the hosts' local disks. Tick it to size that data as well. RVTools exports do not report local storage.

Growth Projection

OptionDefaultWhat it does
Projection Years5How many years of growth the cluster must absorb (1–5).
YoY Growth %10Growth per year, compounded. 10% over 5 years is about 1.61 times today's workload.
Snapshot Overhead %20Extra storage reserved for snapshots, on top of the grown data.
Max Day-One Storage % (advanced)50A cap on how full the storage may be on day one, before growth, as a share of the whole cluster's usable capacity. It adds headroom on top of growth and snapshots. 100 means no cap.
Max Day-One RAM % (advanced)50The same for RAM, but measured against the RAM that is left with one node down (N-1). That is why the RAM bar on the cards, which is drawn against the full cluster, reads lower than this percentage. 100 means no cap.
Licence Term (advanced)5 yearsHow many years of SC//HyperCore licence and support to price (1–5). This is independent of Projection Years: a customer can buy 3 years of licence on a cluster sized for 5 years of growth.
Guest Licensing (advanced)Detected, else WindowsSoftware in the VMs that is licensed per physical core: None (Linux/BSD), Windows, or Windows + core-billed DB (SQL Server, Oracle). Many cores per node make such software more expensive, so the sizer weighs that when ranking. It is detected from the imported guest operating systems. A core-billed database cannot be detected, so select it yourself when there is one. Once you change it, your choice sticks.

Under the growth options, four cards show the workload today and at the end of the projection: vCPUs, RAM, GHz and storage (including snapshots), plus the IOPS the workload needs.

CPU performance

Newer CPUs do more work per GHz than old ones. When the source CPU's benchmark score is known (step 2, Source CPU), each recommendation shows how the new CPUs compare with the current ones, and the {{ m.ui("Explanation") }} button shows the calculation. Depending on how the administrators have configured the sizer, the score can also lower the amount of compute needed. The card then shows a compute floor line and can say Determined by Compute.

{% call m.tip() %}Always check the source CPU score on step 2. A missing or wrong score makes the performance comparison meaningless.{% endcall %}

Redundancy is built in

There is no switch for redundancy: every recommendation keeps the workload running with one node down (N-1) for RAM and, unless you tick Size CPU for full cluster, for CPU. Data is always stored twice, on different nodes, so it survives a node loss. The usable storage figures already account for that second copy.
