A BOM check reads a partner's bill of materials or quote and checks every part against the Scale Computing hardware compatibility list (HCL). When you link it to a sizing, it also checks whether the quoted hardware is big enough for that sizing.

Running a check

  1. On the project page choose {{ m.ui("Check a BOM") }}.
  2. Drop the file on the upload area, or click it to browse. Excel, CSV and PDF are accepted, up to 10 MB. When the AI reader is available, pictures (PNG, JPEG, WebP) are accepted too.
  3. Under {{ m.ui("Check against a sizing") }}, choose the sizing the quote is for, or Compatibility check only (no sizing).
  4. Optionally give the check a name. It defaults to the file name.
  5. Choose {{ m.ui("Check BOM") }}.
{{ m.shot("bom-upload", "Check a BOM: the upload step") }}

The formats the checker reads directly are listed under Recognised layouts and the blank template: the Lenovo DCSC export, the Dell service-tag export, Dell quotes, and the SC// BOM template. For any other layout, {{ m.ui("Download the blank template") }} gives you a spreadsheet to fill in.

Files in another layout

When the checker does not recognise the layout, a Claude AI agent reads the file instead. That takes a little longer. You can close the dialog: the result appears under BOM checks on the project page. Tick {{ m.ui("Email me when the check is done") }} to be notified.

A check read by the agent carries a banner saying so. It can also warn about lines it could not match to the document, text hidden in the file, or content that looked like instructions to the agent. Such lines are dropped. {{ m.ui("Download the pre-filled template") }} gives you the parts as the agent read them, in the template layout, so you can correct them and check the file again. Agent-read checks may be reviewed by Scale Computing. The result then shows Reviewed by Scale Computing with the reviewer's note.

When a file cannot be read at all, you are asked whether Scale Computing may keep a copy to improve the checker ({{ m.ui("Share the file with Scale Computing") }} or {{ m.ui("No thanks") }}). A shared file is deleted after 90 days. The agent has daily limits. When they are reached, the checker says so. Try again later or use the template.

The result

{{ m.shot("bom-result", "A BOM check result") }}
  • Technical: PASS, FAIL or INCONCLUSIVE. Did every part check out against the HCL?
  • Fit: compared with the linked sizing: Matches sizing, Fits, Bigger than sized, Undersized or Fit unknown.
  • Per configuration in the quote, the platform it was identified as, and a table of findings: severity (Error, Warning, Info), component, issue and what to do about it.
  • Suggested swaps propose HCL-listed parts to use instead of a problem part. A TCE badge marks a Trusted Compatibility Entry.
  • The Sizing fit table compares the quote with the requirement and with the recommendation, per dimension: nodes, CPU cores, compute performance, RAM with a node down, largest VM, usable storage and NIC speed.

{{ m.ui("Re-check against") }} runs the same file against another sizing, or against the current HCL after it has changed. {{ m.ui("Check another BOM") }} starts a new check, and {{ m.ui("Delete") }} removes this one.

BOM checks on the project page

Every check is listed on the project page with its verdicts. Click one to open it again. The {{ m.ui("Check a BOM") }} button shows how many checks the project has.
