{{ m.ui("Comparisons") }} on the project page puts sizings side by side. It is a three-step dialog.

{{ m.shot("compare-mode", "Step 1: compare individual sizings, or tag groups") }}

Comparing individual sizings

  1. Choose {{ m.ui("Individual sizings") }}.
  2. Tick two or more sizings. {{ m.ui("Compare") }} becomes available once two are ticked.
  3. The table shows the chosen option of each sizing: model, clusters, nodes, cores, RAM, usable storage, and cores and RAM with one node down. The Why this option row shows the notes from the Options panel.
{{ m.shot("compare-pick", "Step 2: pick what to compare") }} {{ m.shot("compare-result", "Two alternatives side by side") }}

Under the table the sizer adds up the sizings that are Part of the total. If they are all alternatives, it says there is no combined total, because competing options are never summed.

Comparing tag groups

When the sizings are tagged into solution sets (for example Option A and Option B, each made of several sizings), choose {{ m.ui("Tag groups") }}. All tags start ticked. Untick the ones you do not want. Each column is then a whole solution set, with its members listed.

{{ m.shot("compare-tags", "Comparing two tag groups") }}

Reading the comparison

  • Every column after the first shows the difference (Δ) from the first column.
  • Warnings appear above the table when the comparison may mislead: sizings with mixed roles, sizings sized under different sizing rules, sizings that are not sized, need a refresh, or need a re-import.
  • {{ m.ui("Export CSV") }} and {{ m.ui("Export Excel") }} download the table.
  • {{ m.ui("Back") }} returns to the previous step. Closing the dialog clears it.
