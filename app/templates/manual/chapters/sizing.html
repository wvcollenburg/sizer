Choose {{ m.ui("New sizing") }} on a project (or {{ m.ui("Quick sizing") }} on the Projects screen). The sizer opens with a bar showing the project and sizing you are in, a {{ m.ui("← Back to project") }} button, and four modes.

{{ m.shot("sizer-appliance-empty", "A new sizing opens in Appliance mode") }}

The four modes

ModeUse it when
{{ m.ui("Appliance (Certified)") }}You already know which SC// appliance and how many nodes, and want to see what that cluster delivers. A calculator, not a recommendation.
{{ m.ui("Software Only (Validated)") }}You want to check a specific software-only (validated) server configuration against the installer rules.
{{ m.ui("Assessment Import") }}You have an assessment export of the existing environment. This is the normal way to size.
{{ m.ui("Manual Input") }}You have no export, but you know the workload totals (vCPUs, RAM, storage), or you want to type in a list of VMs.

Switching modes starts from scratch: nothing carries over. If you have unsaved work, the sizer asks first:

{{ m.shot("leave-page", "Unsaved work is never discarded without asking") }}

{{ m.ui("Stay here") }} cancels, {{ m.ui("Discard & switch") }} throws the work away, and {{ m.ui("Save & switch") }} saves it first.

Assessment Import

Supported sources:

  • Live Optics: the VMware collector, the Hyper-V collector, and the physical-server scan. Live Optics exports are the richest source: they include performance data (CPU, memory, IOPS).
  • RVTools: inventory only. It has no performance data and no local storage figures.
  • Nutanix Collector.

Upload the .xlsx file as it came out of the tool. Do not re-save or edit it in Excel first. The sizer recognises the source by itself. An incomplete export is refused with a message that says what is missing (for example datastores account for only X of Y VMs).

The guided import wizard

By default an import runs as a five-step wizard. The steps are shown across the top. Once you have reached a step you can click it to go back to it. {{ m.ui("Back") }} and {{ m.ui("Next") }} move one step at a time.

{{ m.shot("wizard-upload", "Step 1: Upload") }}

Several clusters in one file

When the export contains more than one cluster, the sizer asks what to do with them:

{{ m.shot("fanout", "Multiple clusters detected") }}
  • {{ m.ui("Create N sizings") }} (recommended) creates one sizing per ticked cluster in the project, each named after its cluster, with the role Part of the total and the tag shown in {{ m.ui("Tag these sizings") }}. Untick clusters you do not want. Clear the tag field to create them without a tag. You are taken back to the project page, where the new sizings are marked To be sized. Nothing is sized until you open each one and save it.
  • {{ m.ui("Size as one combined cluster") }} treats the whole file as a single workload. Choose this only when the clusters really are being consolidated into one new cluster.
{{ m.shot("project-to-be-sized", "One sizing per cluster, waiting to be reviewed") }}

Step 2: Environment

A summary of what the file contains. Check that it looks right before going on.

{{ m.shot("wizard-environment", "Step 2: the environment and the workload it runs") }}
  • The top rows describe the current hardware: platform, cluster, hosts, VMs, cores, threads, RAM, peak and average CPU and memory use, and IOPS.
  • P95 IOPS can be typed in when you know it, for example from the Live Optics dashboard. The export itself does not contain it.
  • Source CPU · SPECrate2017 is the benchmark score of the current CPUs. It is filled in automatically when the CPU is recognised. Choose {{ m.ui("edit / add") }} to check or enter it yourself (SPECrate2017 or PassMark, per detected CPU). This score lets the sizer compare the performance of the old and new CPUs, rather than only their clock speed.
  • The Workload Requirements row shows what will be sized: vCPUs, provisioned and used RAM, provisioned storage, and datastore use.
  • A box headed A few things to be aware of about this import appears when the data has gaps: for example no performance data, no IOPS data, storage that is only on local disks, hosts that are not in a cluster, or a vCPU ratio that had to be assumed (physical-server scans).
{{ m.shot("source-cpu", "Source CPU performance: benchmark scores per detected CPU") }}

Step 4: Sizing

The sizing options, with sensible defaults already applied. Most sizings need no changes here. {{ m.ui("Show advanced options") }} reveals the rest. Every option is explained in Sizing options.

Step 5: Recommendations

The ranked recommendations. Reading them is explained in Reading the results. {{ m.ui("Save and close") }} saves the sizing and takes you back to the project. {{ m.ui("Start over") }} returns to step 1.

The classic view

{{ m.ui("Switch to classic view") }} (top right of the wizard) shows everything on one page: upload, environment summary, sizing options on the left and recommendations on the right. Experienced users often prefer it. The VM review is then behind a {{ m.ui("Configure VMs") }} button, which opens the same list in a dialog. Its {{ m.ui("Apply Changes") }} button applies your exclusions. {{ m.ui("Switch to guided wizard") }} goes back. Both views share the same data, so switching never loses work. Your choice is remembered.

Manual Input

For when there is no assessment export.

{{ m.shot("manual-form", "Manual Input") }}
  • Current Environment (all optional): the existing platform, hosts, cores, threads, GHz, RAM, CPU and memory use, IOPS and NIC speed. Filling in cores lets the sizer show the current vCPU:core ratio. Filling in IOPS gives it a storage performance target.
  • Workload Requirements: the fields marked * are required: total vCPUs, provisioned RAM, and datastore used.
  • {{ m.ui("+ Add / edit VMs") }} opens a VM list you can type into, with clone (copies with automatic numbering, for example DC01 → DC02, DC03…) and remove per row. {{ m.ui("Apply") }} raises the workload totals to at least the sum of the VMs, and the totals cannot then be set lower than that sum.
  • {{ m.ui("Get Recommendations") }} sizes it. The options and results are the same as for an import.
{{ m.shot("manual-vms", "Add VMs by hand") }} {{ m.shot("manual-results", "Manual input results: the same options and recommendations as an import") }}

Appliance (Certified)

A calculator for one fixed configuration. Choose {{ m.ui("Show Models") }} (active only, or including end-of-life and end-of-support models), the {{ m.ui("Model") }} and the {{ m.ui("Node Count") }}, then the CPU, RAM, NIC and drive options that model offers. You can add storage-only nodes (at least two full nodes are required). Every change recalculates straight away.

{{ m.shot("appliance-form", "Appliance mode: pick the model and its options") }} {{ m.shot("appliance-results", "Per node, the cluster total, and what is left with one node down") }}

The three cards show one node, the whole cluster (with the licence it needs), and N-1: what is still available while one node is down for an update or a failure. Size the workload against the N-1 figures. A two-node cluster also shows a reminder that it needs a witness.

Software Only (Validated)

For checking a server configuration that is not an SC// appliance. Enter the node count, cores, threads, base GHz, RAM and NIC per node, and the disk layout (single tier, or dual tier/hybrid with a capacity tier and a fast tier). The Validated Installer Rules checklist lights up as each rule is met:

  • At least 2 disks per node (3 or more preferred).
  • Hybrid: the fast tier must be between the configured minimum and maximum share of capacity (7–25% by default), with at least 2 HDDs per flash disk.
  • JBOD and internal storage only.
  • At least 2 nodes (a 2-node cluster needs a witness).

{{ m.ui("Calculate") }} shows the same three cards as Appliance mode.

{{ m.shot("validated-form", "Software Only (Validated): the configuration and the installer rules") }}

Saving a sizing

Save with {{ m.ui("Save sizing") }} in the header, the {{ m.ui("Save sizing") }} button above the recommendations, or {{ m.ui("Save and close") }} at the end of the wizard.

  • A new sizing asks for a name, and is filed in the project you are in (or your personal scratch project when you started a Quick sizing).
  • When you change a sizing you own, the sizer asks whether to {{ m.ui("Update") }} it or {{ m.ui("Save as new") }}. Save as new is how you create an alternative: for example the same import sized all-flash.
  • After saving you see the sizing's 12-digit share code, with a {{ m.ui("Copy") }} button.
{{ m.shot("save-choice", "Update the sizing, or save a copy as a new one") }} {{ m.shot("name-sizing", "Naming a new sizing") }} {{ m.shot("saved-code", "Saved, with the share code") }}

The {{ m.ui("Save sizing") }} button above the recommendations shows a dot while there are unsaved changes, and reads Saved when there are none.
